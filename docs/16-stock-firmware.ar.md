# ١٦ — تشغيل المشترِكات بالبرنامج الأصلي بدون تحديث الفلاشة

**قد لا تحتاج المشترِكات إلى تحديث برنامجها الثابت إطلاقًا.** إذا كانت من عائلة
LG U+ / Jinheung MTTL فإن برنامجها الأصلي يتحدث ببروتوكول نصي بسيط إلى عنوان
خادم مخزَّن في ذاكرتها — ويمكن تغيير هذا العنوان بسطرين عبر نقطة وصول الإعداد
الخاصة بالمشترك نفسه.

هذا يُلغي المرحلة B بالكامل من [`12-test-plan.md`](12-test-plan.md): بدون فتح
الغطاء، بدون UART، بدون `tuya-cloudcutter`، وبدون إبطال شهادة KC.

> مصدر البروتوكول: وثّقه مشروع [`powerk`](https://github.com/bahaajobs/powerk).
> لا يحتوي ذلك المستودع على ملف ترخيص، لذا فحقوقه محفوظة؛ والملف
> `server/src/mttl.js` هنا تنفيذ مستقل للبروتوكول ولا يشترك معه في أي كود.

## أولًا: هل هذا جهازك فعلًا؟

**غير مؤكَّد.** مشروع `powerk` يستهدف مشتركًا بأربعة مخارج **بدون أي منافذ USB**،
بينما المشترك في الصورة الأصلية يحتوي ٤ مخارج **ومنفذَي USB**. قد يكون نفس
العائلة بمنفذ USB دائم التشغيل، وقد يكون طرازًا مختلفًا. لم يتحقق أحد بعد.

الاختبار رخيص ولا يحتاج أدوات:

1. اضغط زر المشترك الرئيسي ~١٠ ثوانٍ حتى يومض المؤشر بسرعة.
2. ابحث عن شبكة واي فاي باسم `TONLY_TAP_XXXXXXX` (كلمة المرور `LGU_XXXXXXX`).
3. اتصل بها ونفّذ أمر الإعداد أدناه.

إذا ردّ المشترك بـ `up:ip:ip_ok` فهو من هذه العائلة وكل ما يلي ينطبق. إذا لم
تظهر الشبكة فهو ليس منها، وتبقى مسارات تحديث الفلاشة في
[`03-firmware-tracks.md`](03-firmware-tracks.md) هي الحل.

جرّب على **وحدة واحدة** قبل التخطيط لأي شيء بناءً على ذلك.

## طريقة العمل

المشترك يخزّن عنوان خادم **واحدًا** ويتصل به على منفذ TCP 10086. الاتصال يخرج
**من المشترك إلى الخادم**، ولهذا لا يحتاج الراوتر المنزلي لفتح أي منفذ، ويعمل
نفس الخادم سواء كان داخل المنزل أو على VPS. هذا حل أفضل لمشكلة CGNAT من تحويل
المنافذ المذكور في [`13-direct-mode.md`](13-direct-mode.md).

المقايضة بوضوح: **التحكم المباشر من الهاتف إلى المشترك مستحيل بالبرنامج الأصلي**،
لأن المشترك لا يكلّم إلا خادمه الوحيد. فإما:

- **برنامج أصلي** — بدون تحديث فلاشة، لكن يجب تشغيل خادم دائمًا، أو
- **فلاشة محدَّثة** — بدون أي خادم، لكن يجب فتح كل وحدة.

الخادم يمكن أن يكون راسبيري باي في المنزل؛ ليس شرطًا أن يكون VPS.

## التشغيل

```bash
npm install
PC_MTTL_ENABLED=1 npm start
```

ثبّت عنوان IP للجهاز في الراوتر — المشترك يتذكر العنوان، وتغييره يعني إعادة
الإعداد من جديد.

ثم، والمشترك في وضع الإعداد وجهازك متصل بشبكة `TONLY_TAP_*`:

```bash
node tools/provision-mttl.js --ip 192.168.1.14 --ssid "اسم الشبكة" --password "كلمة المرور"
```

يرفض الأمر أي اسم شبكة أو كلمة مرور تحتوي `:` أو سطرًا جديدًا، لأن البروتوكول
يفصل بالنقطتين وسيقتطعها بصمت.

ثم من التطبيق: **الإعدادات ← طريقة الاتصال ← عبر خادم**، أدخل عنوان الخادم
وسجّل الدخول. كل شيء آخر يعمل كما هو: العربية، المواعيد، السجل، قطع الاستعداد،
الحمل الزائد، وشرائح التعريفة.

## ميزة لا تملكها الفلاشة المحدَّثة

**قياس لكل مخرج على حدة.** بروتوكول MTTL يرسل القدرة والطاقة **ودرجة الحرارة
لكل قناة**. المشترِكات المحدَّثة تملك مقاومة قياس واحدة قبل المفاتيح الأربعة،
فلا تستطيع قياس أكثر من المشترك ككل.

## الاختبار بدون أجهزة

```bash
PC_MTTL_ENABLED=1 npm start     # نافذة ١
npm run mttl-sim                # نافذة ٢
```

`npm test` يغطي هذا المسار كاملًا — مشترك وهمي يتصل ويسجّل نفسه ويُتحكَّم فيه
عبر نفس واجهة REST التي يستخدمها التطبيق، **وبدون أي وسيط MQTT**.

للتفاصيل الكاملة والبروتوكول والأمان: [`16-stock-firmware.md`](16-stock-firmware.md).
